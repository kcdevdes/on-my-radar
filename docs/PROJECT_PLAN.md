# On My Radar — 서비스 기획서

작성일: 2026-09-24  
상태: 초기 기획안 · 아래 범위와 수치는 검증을 위한 제안

관련 문서: [서비스 순서도 — 단계별 조건과 AI 사용 지점](./SERVICE_FLOW.md)

## 1. 서비스 개요

**좋아하는 아티스트의 공연과 예매 일정을, 내가 갈 수 있는 지역에 맞춰 알려주는 서비스.**

사용자가 관심 아티스트와 관람 가능 지역을 등록하면 공식 출처에서 공연 정보를 수집하고, 신규 공연·예매 및 추첨 접수 일정·중요 변경 사항을 이메일로 전달한다.

### 해결하려는 문제

- 공연 정보가 아티스트 홈페이지, SNS, 주최사, 예매처에 흩어져 있다.
- 해외 아티스트의 공지를 계속 확인하고 외국어로 된 신청 조건을 이해하기 어렵다.
- 공연 소식을 알아도 예매 시작이나 추첨 접수 마감을 놓칠 수 있다.
- 거주 지역 밖이나 해외 공연도 관심 있지만, 모든 지역의 소식을 받고 싶지는 않다.

### 초기 대상 사용자

한국 또는 일본에서 일본 아티스트의 공연을 관람하려는 한국어 사용자. 초기에는 정보 수집 경로가 확보된 아티스트 10~20팀으로 시작한다.

## 2. 사용자 흐름

1. 관심 아티스트를 검색하고 여러 명 선택한다.
2. 관람 가능한 국가를 선택한다. 예: 한국만 / 일본만 / 한국과 일본.
3. 알림받을 이메일을 입력하고 주소를 인증한다.
4. 이미 발표된 예정 공연을 확인한다.
5. 새 공연이나 예매 일정이 확인되면 알림을 받는다.
6. 이메일의 링크로 관심 아티스트·지역·알림 설정을 변경하거나 구독을 해지한다.

**예시:** 바운디를 선택하고 관람 지역을 한국과 일본으로 설정한 사용자는 두 국가의 공연 소식과 관련 예매·추첨 접수 일정을 받는다. 다른 국가의 공연은 제외한다.

## 3. 핵심 기능

| 기능 | 내용 |
|---|---|
| 아티스트 구독 | 여러 아티스트 선택, 한글·영문·현지어 이름으로 검색 |
| 관람 지역 설정 | 첫 버전은 한국·일본 국가 단위 복수 선택 |
| 예정 공연 조회 | 구독 직후 이미 발표된 공연을 한 번에 확인 |
| 신규 공연 알림 | 아티스트, 공연 날짜, 도시, 공연장, 공식 출처 전달 |
| 예매 일정 알림 | 일반 예매·팬클럽 선예매·추첨 접수 구분, 시작·마감 안내 |
| 일정 리마인더 | 확인된 신청 시작·마감에 대해 사용자가 선택한 알림 발송 |
| 중요 변경 알림 | 취소·연기, 장소·시간 변경 전달 |
| 구독 관리 | 이메일 인증, 설정 변경, 구독 해지 |
| 운영 화면 | 수집 상태, 검수 대기, 중복 공연, 발송 오류 확인 |

### 지역 설정 원칙

- 거주지와 관람 가능 지역은 분리한다. 국가 선택만 사용하는 첫 버전에서는 거주 도시를 필수로 받지 않는다.
- 확장 시 국가·도시·거주 도시 기준 반경을 지원한다. 거리 단위는 km와 mi를 제공한다.
- 복수 지역 조건 중 하나라도 충족하면 알림 대상에 포함한다. 예: 한국 전체 또는 도쿄.
- 거리 기반 기능을 도입할 때 직선거리인지 이동거리인지 명시한다.
- 이후 공통 지역 설정을 아티스트별로 변경할 수 있도록 확장한다.

## 4. 정보 수집과 AI 활용

### 출처 우선순위

1. 아티스트 공식 홈페이지의 NEWS·LIVE 페이지
2. 공식 주최사·공연장·예매처
3. 서비스 목적에 맞는 사용이 허용된 공연 데이터 API
4. 접근 가능 여부를 확인한 공식 SNS

초기에는 아티스트별 공식 출처를 운영자가 등록한다. 모든 SNS를 수집할 수 있다고 가정하지 않으며, 각 출처의 이용 조건과 접근 제한을 확인한다. 지원하지 않는 아티스트는 신청받아 수집 가능성을 검토한다.

### 처리 흐름

```text
등록된 출처 주기적 확인
  → 새 공지 또는 본문 변경 감지
  → 공연 관련 후보 선별
  → 규칙 기반 추출, 필요한 경우 AI 분석
  → 날짜·장소·출처 검증
  → 동일 공연 통합 및 변경 사항 비교
  → 사용자별 관심 아티스트·지역 매칭
  → 이메일 발송
```

### 비용 절감 원칙

- 사용자별로 수집하지 않고, 출처별로 한 번 수집한 결과를 모든 구독자에게 활용한다.
- API나 일정한 페이지 구조로 추출 가능한 정보는 AI 없이 처리한다.
- 공지 본문의 변경 여부를 확인하고, 같은 콘텐츠는 다시 분석하지 않는다.
- 자유로운 문장 해석·번역이나 이미지에만 있는 일정 추출에 AI를 사용한다.
- 관련 키워드는 다국어로 관리하고, 선별 과정의 누락 여부를 표본 검수한다.
- 출처 제한에 맞춰 확인 주기를 조정하고, 실제 탐지 지연을 측정한다.

운영비는 수집, AI 분석, 이메일 발송, 인프라, 운영·검수 시간을 구분해 측정한다. 월 비용은 초기 실험 결과를 바탕으로 산정한다.

## 5. 정보 품질과 알림 원칙

- **공연과 공지를 분리한다.** 하나의 공연에 홈페이지·SNS·예매처 공지를 연결한다.
- 같은 공연의 중복 공지는 재발송하지 않는다. 예매 일정 추가처럼 의미 있는 변경은 다시 알린다.
- 여러 날짜의 공연과 회차는 별도로 식별하고, 단독 공연·페스티벌 출연을 구분한다.
- 공연일, 접수 시작·마감일, 당첨 발표일을 별도 항목으로 관리한다.
- 팬클럽 가입·현지 전화번호 등 신청 조건은 공식 출처에서 확인된 내용만 표시한다.
- 미확인 정보는 추측하지 않는다. 초기에는 애매한 결과를 운영자가 검수한다.
- 현지 시간대를 저장하고 알림에 명시한다. 사용자 시간대가 설정되어 있으면 함께 표시한다.
- 수집 실패를 ‘공연 없음’으로 처리하지 않는다. 마지막 성공 시각과 오류를 운영 화면에 표시한다.
- 발송 이력을 기록해 재시도 시 같은 알림이 중복 전달되지 않도록 한다.

### 이메일에 포함할 정보

아티스트·공연명, 공연 날짜와 장소, 알림 사유, 확인된 예매·접수 일정, 신청 조건, 공식 공지·예매 링크, 설정 변경·구독 해지 링크.

## 6. 초기 개발 범위

| 첫 버전에 포함 | 이후 검토 |
|---|---|
| 아티스트 10~20팀 | 사용자 요청에 따른 아티스트 확대 |
| 한국·일본 국가 필터 | 도시·거리 필터, 아티스트별 지역 설정 |
| 공식 웹페이지 중심 수집 | SNS 수집 확대, 추가 데이터 제휴 |
| 이메일 알림 | 디스코드·카카오톡 등 추가 채널 |
| 신규 공연·예매 일정·중요 변경 | 캘린더 연동, 추가 개인화 |
| 운영자 검수와 수집 상태 확인 | 검증된 유형의 자동 처리 확대 |

티켓 구매 대행, 자동 예매, 항공·숙소 추천, 실시간 잔여 좌석 추적은 초기 범위에서 제외한다. 예매는 공식 예매처로 연결한다.

### 최소 데이터 구성

- **아티스트:** 고유 ID, 이름과 별칭, 공식 출처
- **공연:** 출연 아티스트, 유형, 국가·도시·공연장, 일시·시간대, 상태
- **신청 일정:** 대상 공연, 예매·추첨 유형, 시작·마감, 신청 조건, 공식 링크
- **출처 공지:** 원문 URL, 확인 시각, 추출 근거, 연결된 공연
- **구독:** 인증된 이메일, 관심 아티스트, 지역, 알림 설정
- **발송 이력:** 수신자, 공연·변경 항목, 발송 상태

## 7. 검증 계획

본격 확장 전에 2~4주간 소수 사용자와 운영자 검수를 병행한다. 해당 기간에 신규 공지가 적으면 과거 공식 공지도 수집·추출 검증에 활용하되 실제 사용자 알림과 분리한다.

| 검증 항목 | 측정 방식 |
|---|---|
| 탐지 누락 | 직접 확인한 대상 공식 공지 중 시스템이 탐지한 비율 |
| 탐지 속도 | 확인 가능한 공지 게시 시각부터 알림까지의 지연 |
| 알림 정확도 | 잘못된 날짜·지역·아티스트 연결 및 중복 발송 건수 |
| 사용자 가치 | 알림을 통해 신청했거나 새로운 공연을 알게 된 사례 |
| 운영 가능성 | 아티스트별 수집·분석 비용과 주간 유지보수·검수 시간 |

실험 후 지원 범위와 확인 주기를 조정하고 확장 여부를 결정한다. 유료 구독 모델은 공연 소식의 빈도와 사용자 지불 의향을 확인한 뒤 정한다.

## 8. 개발 전 확정할 사항

- 첫 지원 아티스트 목록과 각 아티스트의 공식 수집 출처
- 출처별 접근 가능 여부, 확인 주기, 운영 비용 상한
- 리마인더 기본 시점과 사용자 설정 범위
- 자동 발송 가능한 정보와 운영자 검수가 필요한 정보의 기준
- 초기 실험의 정확도·지연·운영 시간 목표
